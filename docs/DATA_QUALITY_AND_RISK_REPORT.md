# QMT 本地数据库数据质量与风险报告

> 报告编号：DQR-20260823-001
>
> 报告日期：2026-08-23（Asia/Shanghai）
>
> 数据根目录：`E:\qmt_data`
>
> 当前状态：`OPEN / DEFERRED`
>
> 最高风险等级：`HIGH`

## 1. 执行摘要

当前 MiniQMT/xtquant 环境可以读取当前 A 股日线、主要指数、财务数据和过期 CFFEX
合约，但执行 `download_history_contracts()` 后没有出现官方文档所述的“过期上证A股”、
“过期深证A股”或“过期沪深A股”板块。因此程序不能可靠枚举历史退市 A 股，也不能证明
历史证券全集不存在幸存者偏差。

本问题不等同于“退市股票行情一定不存在”。目前只能确认：**当前连接环境没有提供可验证的
退市 A 股发现入口**。根因可能涉及客户端数据管理状态、下载后未重启、券商版/行情源差异、
版本或 xtdatacenter 初始化方式，尚未最终定因。

根据项目负责人决定，本问题暂缓处理。Phase 0 完整库硬门禁继续生效，不批准把当前名单
伪装为完整历史证券全集；项目负责人另行接受风险，允许构建明确标记为
`CURRENT_UNIVERSE_ONLY` 的临时部分库。

## 2. 实机证据

运行环境：

```text
xtquant version: xtquant_250807
data root: E:\qmt_data
download_history_contracts: completed
```

去敏检查结果：

| 检查项 | 状态 | 证据/说明 |
|---|---|---|
| 当前 A 股日线 | PASS | `000001.SZ` 返回有效日线 |
| 历史合约列表下载命令 | PASS | 同步命令正常返回 |
| 过期 A 股板块 | EMPTY | 下载后筛选“过期 + A股”的板块结果为空 |
| 退市 A 股候选发现 | EMPTY | 无合法候选代码 |
| 退市 A 股历史日线 | BLOCKED | 因无候选，不能进行有效样本验证 |
| 过期 CFFEX 合约发现 | PASS | 运行时可发现过期真实合约 |
| 过期 CFFEX 日线 | PASS | 样本具备 OHLC、结算价、成交量和持仓量 |

普通 `沪深A股` 板块使用 `real_timetag` 查询 2015、2018、2020、2024 等日期时，实机
返回数量没有表现出可信的历史变化，不能作为退市证券全集来源。

官方资料说明，退市标的应在下载历史合约信息后从“过期”板块读取：

- [XtData 行情模块：下载过期（退市）合约信息](https://dict.thinktrader.net/nativeApi/xtdata.html)
- [行业概念数据：获取板块退市股票数据](https://dict.thinktrader.net/dictionary/industry.html)

## 3. 数据质量评估

| 质量维度 | 评级 | 说明 |
|---|---|---|
| 当前证券行情完整性 | 可用 | 当前 A 股有效样本已验证 |
| 历史证券覆盖完整性 | 不合格 | 无法证明包含全部退市股票 |
| 时间一致性 | 未通过 | 历史 universe 无法完成四年份验证 |
| 来源可追溯性 | 部分通过 | 实机报告与版本已记录，但退市元数据来源缺失 |
| PIT 财务语义 | 代码已验证 | 不消除历史证券全集缺失风险 |
| 期货历史样本 | 不合格 | 仅发现 12 个近期 IF/IH/IC 合约；没有 IM 或完整历史合约主表 |
| 全量数据库验收 | 阻断 | Phase 0 五项硬门槛未全部 PASS |

## 5. 使用限制

在风险关闭前：

- 不得宣称已建成无幸存者偏差的 2011 年以来 A 股数据库；
- 不得用当前 A 股列表执行历史全市场回测并作为正式研究结论；
- 不得把缺失的退市记录解释为“当时不存在”；
- 可以继续进行代码开发、合成测试、当前行情样本和期货样本验证；
- 经项目负责人确认，可以构建临时部分库，但必须标记 `CURRENT_UNIVERSE_ONLY`，且不得与
  正式无偏回测库混用；
- 临时股票池必须命名为 `CURRENT_SURVIVORS`，不得命名为 `ALL_A`。
- 当前 `future_daily`、`future_main_mapping`、`future_basis_daily` 仅供诊断；在 FUT-001/FUT-002
  关闭前，不得用于正式期货策略、换月收益或基差回测结论。

## 6. 后续处置方案

按优先级执行：

1. 在 MiniQMT 的“数据管理 → 过期合约数据 → 过期合约列表”完成下载并重启客户端；
2. 重跑 `download_history_contracts()`，检查全部包含“过期”的 A 股板块及其证券数量；
3. 核查当前券商版 MiniQMT、xtquant 版本、行情源和账号是否提供退市证券元数据；
4. 如本地 MiniQMT 入口仍为空，评估使用合规的 xtdatacenter 初始化方式；
5. 仍无法取得时，引入交易所或其他权威证券主表，保存来源版本、抓取日期和 checksum；
6. 修复程序发现逻辑：当前板块与过期板块分别读取后做 union，不再依赖普通 A 股板块的
   历史日期差集；
7. 重新执行 Phase 0，并更新本报告状态。

期货历史库另行执行：取得权威 IF/IH/IC/IM 历史合约主表；按真实生命周期下载日线；
过滤 `trade_date < list_date`、到期后记录、空价格和零占位记录；重建主力映射与基差，并抽查换月。

## 7. 风险关闭标准

只有以下项目全部满足，才能把状态改为 `CLOSED` 并允许全量初始化：

- [ ] 获得可重复生成的当前 + 退市 A 股完整证券主表；
- [ ] 每条证券保留来源、上市日和退市日，未知值不推测；
- [ ] 至少一只退市股票的静态资料和上市期历史日线验证 PASS；
- [ ] 退市后没有伪造行情；
- [ ] 2015、2018、2020、2026 四个年份的历史 universe 数量变化合理；
- [ ] Phase 0 五项硬门槛全部 PASS；
- [ ] 去敏 Preflight、质量摘要和处理决定已归档；
- [ ] Reviewer 确认没有用当前名单替代历史证券全集。
